## Project Overview

flod is an R package for statistical learning on flow cytometry data.
The goal is to get users as fast as possible into a machine learning
context by providing functions to read, transform, and visualize data -
with sensible defaults for flow cytometry. It is developed with the
tidyverse/tidymodels ecosystem in mind, enabling standard data science
workflows on flow cytometry data.

**Key Goals:** 1. Quickly convert flow cytometry data into tibbles for
tidyverse/tidymodels workflows 2. Provide domain-specific functions for
plotting, transforming, and gating familiar to flow cytometry scientists

**Status:** Under heavy development and subject to sweeping changes (see
R/zzz.R:2)

## Core Architecture

### Data Flow

Before we have written our own parser, the primary data structure is
flowCore’s `flowSet` (S4 class) which stores .fcs files. The function
[`to_tibble()`](https://hugoakerstrand.github.io/flod/reference/to_tibble.md)
(R/to_tibble.R) converts flowSet objects into tibbles by extracting: -
`sample_names`: Sample identifiers from pData rownames - `exprs`:
Expression matrices from each flowFrame - `keywords`: Metadata keywords
from each flowFrame - `meta_data`: phenoData from the flowSet

The conversion uses internal getter functions (get_sample_names,
get_exprs, get_keywords, get_meta_data) that abstract flowCore API
calls.

### Dependencies

- **flowCore**: Core dependency for .fcs file handling and
  flowSet/flowFrame classes
- **tibble**: Output data structure
- **cli**: User-facing error messages
- **ggplot2**: Visualization support

## Synthetic Data (`inst/extdata/synthetic_data.duckdb`)

Generated by `data-raw/synthetic_data.R`. A DuckDB database containing 8
tables (`experiment1`–`experiment8`), each with 8 rows (one per sample).
Each row has a single `exprs` column: an array of structs representing
flow cytometry events (~15,000 events per sample).

### Channels per event

| Column         | Type    | Description                            |
|----------------|---------|----------------------------------------|
| `FSC-A`        | double  | Forward scatter area                   |
| `SSC-A`        | double  | Side scatter area                      |
| `FSC-H`        | double  | Forward scatter height                 |
| `FL1-A`        | double  | Fluorescence channel 1 (viability dye) |
| `FL2-A`        | double  | Fluorescence channel 2                 |
| `FL3-A`        | double  | Fluorescence channel 3                 |
| `Live`         | boolean | Viability gate ground-truth label      |
| `Size`         | boolean | Size gate ground-truth label           |
| `Singlet`      | boolean | Singlet gate ground-truth label        |
| `FL2_positive` | boolean | FL2 positive ground-truth label        |
| `FL3_positive` | boolean | FL3 positive ground-truth label        |

### Experiment design

- **Experiments 1–7**: Baseline — normal conditions, ~86–97% live cells
  per sample
- **Experiment 8**: Sample 8 has intentionally low viability (10% live,
  2,000/20,000 events)

The boolean columns serve as ground-truth gate labels for supervised
learning workflows.

## Flow Cytometry Conventions

### Visualization

- Use `geom_hex()` (not `geom_point()`) for 2D scatter plots — flow
  cytometry data typically has tens of thousands of events per sample,
  making hexbin plots the standard choice.

### Transformations

- Use `asinh` transformation for fluorochrome channels (FL1-A, FL2-A,
  FL3-A, etc.) — fluorescence signal can span multiple logs and include
  negative values, making asinh the standard transformation. Scatter
  channels (FSC, SSC) typically use linear scale.
